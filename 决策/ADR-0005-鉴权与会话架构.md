# ADR-0005 鉴权与会话架构

- **状态**：已采纳（2026-10-03 回填建档）
- **日期**：决策/施工日 2026-09-21/22；建档日 2026-10-03（回填建档）
- **决策记录**：内部过程档（决策登记在案；代码注记位=server.py 头注）
- **关联**：hash_passcode.py；tests/test_auth.py（auth 8/8 回归面）；config.example.json（口令/会话键名）

## 背景

产品对外可访问（域名+HTTPS 上线规划在即），须有口令门与滥用防护，同时坚守服务端零第三方依赖纪律（SQLite WAL 标准库持久化）。

## 决策

①**PBKDF2 口令哈希**：服务端只存派生哈希不存明文。
②**会话双轨**：HttpOnly cookie 服务端会话为主轨，body 口令回落为兼容轨。
③**登录限速**：rate_hits 计数（SQLite 持久化）防爆破。
④持久化=SQLite WAL（标准库零依赖）。

## 理由与判据

单机单服务形态下服务端会话+HttpOnly cookie 优于自管 token（XSS 面更小、撤销即删）；PBKDF2 抗离线爆破；零依赖=与"纯标准库优先"一致。

## 替代方案（含被否原因）

- JWT 无状态（弃——单服务无需、撤销难、密钥管理面新增）
- Redis/外部会话存储（弃——零依赖纪律）
- 明文口令比对（弃——密件纪律+爆破面）

## 后果

- **正向**：auth 回归 8/8 常绿；会话/限速状态随 SQLite 持久化可审计。
- **负向/风险**：冒烟工具演进债——deploy_check `--smoke` 口令直发法一度落后于 PBKDF2 cookie 栈（后修=登底动态化）；开发态明文口令与生产 PBKDF2 口令的双态差异曾致一次部署核验冒烟伪红判读（恢复方式归作者决策）。
- **回滚**：架构面无回滚需求；单点行为差异均有备份链。

- 2026-10-07（C3 口令哈希上产；施工报告见内部过程档）：
  - **device 隔离定位校准**：`qabot_device` cookie 是 UX 分区手段（多设备会话归属与历史同步键），**不是授权边界**；授权边界仍唯一=passcode→session token（HttpOnly 会话 cookie）。任何"按设备限权/放行"的提案不在本 ADR 授权面内，须另立 ADR。
  - **口令哈希三键上产（C3）**：config 由明文 `passcode` 键（机制在、生产用明文=摸底安全发现）切至 PBKDF2-HMAC-SHA256 三键（600,000 迭代、常数时间比对）。依据：①配置失陷面下明文键=口令直读，三键=离线研磨成本抬至 600k 量级；②机制与生成器 2026-09-21 已备齐，上产零代码改动可秒级回退；③双态活体+15 例安全单测过。生产侧按 runbook 执行（内部过程档；动生产须作者批准）。明文兼容回退保留为过渡态（无哈希键才生效，启动告警在案），双端齐上产后评估收口。遗留两缺口登记待批：pbkdf2_iterations 无下限校验、双键在位不告警明文残留。
