# ADR-0019 CI门禁化与覆盖率计量

- **状态**：已采纳（2026-10-07）
- **日期**：决策日 2026-10-07；建档日 2026-10-07
- **决策记录**：内部过程档（决策登记在案）
- **关联**：材料档见内部过程档（测试体系计划、只读外审件、测试清单档、覆盖率基线）；CI 零密件零 secrets

## 背景

测试底盘厚（约 2,354 个 unittest 用例、回归网一键实测 183.6-286.8 秒全绿、eval_gate 评测门禁、漂移哨兵在役），但全靠人工记得跑"回归网一键"——烟雾报警器装好未通电。2026-10-07 测试体系盘点+只读外审（33 条意见全采纳）确认四缺口：CI 自动触发、服务端压测、安全测试、覆盖率计量；其中 CI 是其余三缺口的挂载位。外审四个阻断级集中指向同一命题："CI 的绿必须是真绿"（skip 计量、发现范围收口、清单档驱动、异径验收）。

## 决策

①**CI 双层**：私有 GitHub 仓 Actions（push 快子集/PR 全量；三 job=单测/回归网/覆盖率）+ 本机 pre-push 钩子（快子集实测 <60s，含仓库可见性核验）。②**清单档驱动**：CI 挂载件从《测试清单档》（94 件全量摸底产物，85 挂载/9 暂缓）读取，不钉死件数；排除 __init__.py 与回归网一键本体。③**skip 计量硬闸**：三 job 输出 ran/skipped/failed 三元组+skip 原因清单入 artifact；验收=全绿且 skipped≤N（smoke 首轮实测钉死、逐轮下调）。④**发现范围收口**：pytest.ini（testpaths+norecursedirs+--import-mode=importlib）+ coverage --source/--omit。⑤**供应链钉死**：action 全钉 commit SHA、禁 pull_request_target、permissions=contents:read、零 secrets。⑥**覆盖率两期制**：一期只出基线读数与趋势，不设闸；二期 fail_under=基线−2pp 容差闸另批后生效（禁自动生效）。

## 理由与判据

外审实证：①锚件未入跟踪+分词依赖未进清单 → CI 上 skipUnless 条件必然不成立=静默跳过（假门禁，与防自证循环纪律正面冲突）；②全仓 1,675 个 test_*.py（含嵌套 venv 180 件）→ 裸收集必炸；③回归网一键若被当测试件跑会再起 mock_server 抢端口。判据先定后测：skipped 上限 N 由 smoke 首轮实测钉死，不预设。摸底实证（2026-10-07）：86 绿/8 红/9 暂缓——红件（建库 synth/embed 族）分诊后处置，不挂 CI。

## 替代方案（含被否原因）

- 方案A：仅本机 pre-push 钩子（弃因：依赖人手自觉，换 clone 即失效，谈不上自动门禁）。
- 方案B：仅 GitHub Actions（弃因：本地 push 前无快检，红灯要等 push 后才发现）。
- 方案C：覆盖率一期即设 fail_under 硬闸（弃因：低基线+正常波动会误拦，先出基线二期再设容差闸）。

## 后果

- **正向**：推送即自动回归；覆盖率从无计量到有基线；本机↔CI 覆盖差集显性化（记入测试计划 E1）；红件首次被全量照亮。
- **负向/风险**：私有仓 Actions 免费额度 2,000 分钟/月（smoke 实测"单次分钟×频次×30"后回填本档调线记录）；清单档在 paths-ignore 盲区，清单口径变更需手动 dispatch；smoke 与 ci 的 unit job 双胞胎件需手工同步。
- **回滚**：workflow 单文件删除即停（.github/workflows/）；pre-push 卸载一条命令；覆盖率一期纯读数无生产行为；全部不触生产环境与生产 config。外送边界判定：上 Actions=私有仓可控范围，测试零网络零密件，真实档与 config.json 排除在外。
