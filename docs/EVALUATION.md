# 评测体系（EVALUATION）

> 本文说明 specqa 的多卷评测体系设计、防自证机制与门禁线制度，并如实界定公开仓库中的评测资产与完整内部评测体系的关系。

## 一、设计目标

评测不是"跑卷看数"，而是**变更触发阻断**的守护位：换库、拨键、模型栈调整等任何影响问答质量的变更，都必须先过评测门禁，**不通过不放行**。配套纪律：判据先定后测（失败的尺子不悄悄换）、合成题禁入评测。

## 二、多卷题库体系

完整评测题库分六卷、约 400 题，按用途分卷：

| 卷 | 题量 | 用途定位 |
|---|---|---|
| 对抗卷 | 210 | 对抗性/陷阱题主力卷（版本编号类等易错面），带硬线定线（doc 命中 ≥135/180+拒答 abstain ≥20/30） |
| 外部锚点卷 | 64 | 外部基准锚点，对齐可横向比较的第三方判读面 |
| 答案卷 | 44 | 有标准答案的客观题面 |
| 难负例卷 | 36 | 检索负控（hard negatives）：近义但不应命中的干扰块，防"拉深位块上位" |
| 独立 C/Y 卷 | 28+8 | 与调参迭代隔离的独立验收面（C=实操类、Y=意译类） |
| 红线扩容卷 | 20 | 拒答红线题扩容（应拒答/不应拒答两侧） |

各卷判读与两判官制（甲乙一致即定、分歧入裁决队列）、S1 负控两级分层等制度细节见 [../决策/ADR-0008-评测门禁化.md](../决策/ADR-0008-评测门禁化.md)。

## 三、防自证设计：独立命题隔离

评测体系的核心风险是**自证循环**——用同一批题既调参又验收，读数会系统性虚高。本系统的防线：

- **评测题卷与调参迭代分卷**：调参/消融实验只读迭代卷；独立 C/Y 卷等验收卷只用于验收读数。
- **禁止对验收卷反向调参**：任何以验收卷读数为目标的参数调整均属违规；验收卷题面冻结到终验。
- 配套纪律：判据预登记先落盘后测判、失败判据不回溯修改、合成题禁入评测卷。

## 四、门禁线机制

- **单一入口**：`eval_gate.py`（在本仓）统一跑卷与判读。
- **生产门禁线**：门禁线配置（`建库/scripts/门禁线-生产.json`，在本仓）锚定各卷硬线；变更触发的评测不通过硬线即阻断放行（换库/拨键均受护栏约束）。
- 门禁线收紧/放宽均须登记，禁无痕改动。

## 五、公开子集（本仓可见部分）

- **代码测试子集**：本仓 `tests/` 公开 63 件测试、1,340 个用例，全绿（pytest 直跑可复现）。
- **完整内部套件**：95 件、3,229 用例——含依赖内部语料与密件档的用例，在项目方内部维护。
- **公开题卷**：`建库/scripts/题卷/` 公开独立 B/C/Y 三卷共 48 题。**如实说明 transform**：题面中的规范文号已 surrogate 化（替换为同构的代理文号），出处元数据（来源文件/条目指针）已剥离；题目本体、判读口径与内部卷一致，故可用于验收面演示，但不可反推内部语料清单。

## 六、规模证据

完整内部评测套件（95 件 3,229 用例）与 8.3 万块向量库由项目方在内部维护，**可应要求现场演示**（跑卷读数+门禁判读+检索冒烟）。公开仓中的测试子集与公开题卷可独立复现本仓范围内的全部绿读数。
